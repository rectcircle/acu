# ACU 需求文档

## 1. 背景

部分 UI 自动化客户端无法在 macOS 系统锁屏后继续执行任务。用户长时间离开时，系统自动
锁屏会中断正在运行的自动化任务；直接关闭 macOS 自动锁屏又会使物理屏幕和输入设备保持
可用，缺少基本的防窥和防误操作能力。

ACU 是一个独立的 macOS 菜单栏工具，不依赖、不修改目标自动化客户端。
它在用户明确开启后：

1. 运行期模拟轻微用户活动，尽量避免 macOS 因空闲自动锁屏。
2. 使用覆盖全部显示器的保护层模拟锁屏，阻止现场人员查看和操作桌面。
3. 保持自动化客户端对底层应用的截图、Accessibility 和合成输入能力。
4. 仅在 macOS 原生身份认证成功后解除保护。

参考项目：

- `prashantgupta24/automatic-mouse-mover`
- 参考点：仅在系统空闲时，以很小幅度移动并恢复鼠标，而不是持续干扰用户。
- 不直接复用其 UI、状态管理或跨平台依赖。

## 2. 产品定位

### 2.1 安全定位

ACU 提供的是应用层的“隐私保护模式”，不是 macOS 真锁屏：

- 目标是防窥、防止普通现场误操作。
- 通过全屏保护层、物理输入隔离和原生身份认证提供应用层保护。
- 不抵御 root 用户、进程终止、强制重启、恢复模式或具备调试权限的攻击者。
- 不改变登录密码、FileVault、系统锁屏配置或 MDM Profile。
- 不保证绕过所有 macOS 或企业安全策略。

界面和文档必须明确显示“模拟锁屏”，不得使用容易使用户误认为系统已锁定的文案。

### 2.2 企业策略边界

运行期模拟输入也可能违反组织的自动锁屏政策，即使它没有修改系统设置。

- 企业策略检测只用于“权限诊断”中的状态展示，不作为功能开关，也不在开启流程中弹窗。
- 无论检测到托管锁屏策略、仅检测到设备已注册管理，还是无法可靠完成策略检测，用户选择
  开启后都直接进入技术预检。
- 不提供修改、删除或规避 MDM Profile 的能力。
- 诊断结果不表示工具已满足、覆盖或绕过企业策略。

## 3. 用户场景

### 3.1 开启保护

1. 用户确认目标自动化任务正在执行。
2. 用户从菜单栏或快捷键选择“开启模拟锁屏”。
3. 工具执行权限、系统状态和企业策略预检。
4. 工具启动防锁屏活动维护器。
5. 工具在所有显示器展示保护层并拦截物理输入。
6. 自动化客户端在保护层下继续操作目标应用。

### 3.2 解除保护

1. 用户按下物理键盘 Enter。
2. 工具消费该 Enter，不把它发送给底层应用。
3. 工具打开 macOS 原生设备所有者认证面板。
4. 用户通过以下任一方式认证：
   - Touch ID；
   - macOS 原生认证面板提供的系统密码回退。
5. 认证成功后，工具停止活动模拟、移除输入拦截并关闭保护层。
6. 认证取消或失败时保持保护状态。

说明：应用无法也不应被动监听 Touch ID。Touch ID 必须在原生认证面板中使用；MVP 由
物理 Enter 或菜单栏“解除保护”打开该面板。

### 3.3 仅阻止系统锁屏

1. 用户从菜单栏选择“仅阻止系统锁屏”。
2. 工具只启动防锁屏活动维护器，不展示遮罩、不拦截输入。
3. 菜单和状态栏明确显示该模式正在运行。
4. 用户再次选择该菜单项即可停止，无需身份认证。
5. 用户选择开启模拟锁屏时，工具先完成保护预检，再自动停止该模式并进入完整保护态。
6. 模拟锁屏解除后，工具自动恢复此前由用户启用的“仅阻止系统锁屏”模式；用户主动停止
   该模式或退出应用时不恢复。

### 3.4 半合盖自动保护

1. “半合盖自动保护”默认启用，用户可在菜单中关闭或选择触发角度。
2. 屏幕角度低于阈值并稳定后，工具进入完整模拟锁屏保护态。
3. 屏幕重新展开后，工具自动发起原生设备所有者认证，相当于保护态下按下物理 Enter。
4. 认证成功后解除保护；认证取消或失败时继续保持保护。
5. 完全合盖且连接外接显示器时不触发保护，重新展开也不发起认证。

## 4. 功能需求

### FR-1 菜单栏应用

- 仅支持 macOS。
- 不显示 Dock 图标，常驻菜单栏。
- 菜单至少包括：
  - 开启模拟锁屏；
  - 仅阻止系统锁屏；
  - 测试模拟锁屏（15 秒自动退出）；
  - 解除保护；
  - 当前状态；
  - 权限诊断；
  - 半合盖自动保护开关和触发角度；
  - 开启快捷键；
  - 退出。
- 支持可配置的全局快捷键，默认使用 `Control+Option+Command+L`，可切换为其他预设或关闭。
- 全局快捷键仅用于开启保护；已处于保护态时忽略，不得用于跳过身份认证解除保护。

### FR-2 开启前预检

开启模拟锁屏前必须检查：

- 当前处于已登录、未锁定的图形用户会话。
- Accessibility 权限可用。
- Quartz Event Tap 可创建并保持启用。
- LocalAuthentication 至少支持设备所有者认证。
- 至少存在一个可用显示器。

任一关键条件不满足时不得进入保护态，并显示可操作的错误说明。

仅阻止系统锁屏模式只检查当前图形会话、Accessibility、合成事件投递和可用显示器，不得
请求输入监听权限或要求 LocalAuthentication 可用。

上述关键条件仅指功能可靠运行所需的技术条件。企业策略检测是非阻断式诊断，必须区分以下
结果：

- `managed_policy_detected`：明确命中托管自动锁屏策略。
- `managed_unconfirmed`：仅确认设备已纳管，未发现具体锁屏策略。
- `probe_failed`：无法可靠完成检测。
- `allowed`：未发现相关托管策略；继续其他预检。

任何企业策略检测结果都不得弹出确认框、禁用菜单项或使开启操作失败。

### FR-3 空闲活动维护

- 在模拟锁屏保护态或“仅阻止系统锁屏”模式中启用。
- 参考 Automatic Mouse Mover，使用系统活动状态判断是否需要模拟活动。
- 默认在连续 45 秒没有物理或合成 UI 活动后执行一次鼠标轻微移动。
- 鼠标移动幅度默认 1 像素，并在极短时间内恢复原位置。
- 若最近 5 秒存在合成 UI 活动，则推迟本次移动，避免与坐标操作竞争。
- 不在认证面板打开、系统已锁定、显示器休眠或会话切换时移动鼠标。
- 移动失败连续达到阈值时进入故障态，不得继续宣称防锁屏有效。
- 不阻止用户主动合盖、主动睡眠或主动选择 macOS 锁屏。

### FR-4 模拟锁屏保护层

- 覆盖当前全部显示器和全部 Space。
- 背景可配置为当前选择的系统墙纸或纯黑，默认使用系统墙纸。
- 视频墙纸优先复用系统已下载的资源；视频未缓存时先显示首帧，并在后台下载到应用自身
  缓存，下载完成后当前遮罩自动切换。生成式墙纸不受支持，统一回退纯黑。
- 显示产品名、状态和解除提示。
- 定期小幅移动文字位置以降低烧屏风险。
- 屏幕参数变化时自动重建保护层。
- 保护层不激活、不抢占目标应用焦点。
- 保护层自身应尽可能从截图共享中排除。
- 保护层不得包含底层桌面的缩略图或敏感内容。

### FR-5 输入隔离

- 保护态下拦截物理鼠标移动、点击、滚动、拖动和键盘输入。
- 物理 Enter 仅用于发起解除认证。
- 软件产生的合成输入应继续放行。
- 无法可靠区分输入来源时采用安全默认：
  - 物理输入不传递到底层应用；
  - 无法确认来自软件的输入按物理输入处理。
- 认证期间继续放行软件合成输入；物理输入仅定向投递给 macOS 原生认证 UI，不得传递给
  底层应用。
- Event Tap 失效时立即尝试恢复；持续失效则保持遮罩、进入 `degraded` 并在遮罩上方展示
  故障弹窗。弹窗必须提供发起原生身份认证的入口。

### FR-6 原生身份认证

- 使用 LocalAuthentication 的设备所有者认证策略。
- 不实现自有密码输入框。
- 不读取、缓存、记录或传输系统密码。
- 不记录 Touch ID 生物特征相关信息。
- 认证成功是退出保护态的唯一正常路径。
- 15 秒测试模式是首次验收使用的显式诊断路径，遮罩必须显示剩余秒数，并可在超时后无认证
  自动退出；不得用于正式
  保护会话。
- 认证取消、失败、超时或锁定时继续保持保护态。
- 防止重复 Enter 并发创建多个认证请求。

### FR-7 生命周期和恢复

- 开启、关闭操作幂等。
- 应用正常退出前，若仍处于保护态，必须先完成原生认证。
- 收到普通终止请求时不能静默移除保护层。
- 进程崩溃后保护层无法继续存在，因此产品必须明确该方案不是安全边界。
- 启动时不得自动恢复到保护态，避免用户在无可靠认证入口时被困住。
- 不持久化“当前正在保护”的运行状态。

### FR-8 状态与诊断

状态至少包括：

- `disabled`：未启用；
- `arming`：正在预检和启动；
- `awake`：仅防锁屏活动维护正常；
- `protected`：保护和防锁屏均正常；
- `authenticating`：系统认证面板已打开；
- `disarming`：正在停止；
- `degraded`：活动维护或输入拦截异常；模拟锁屏模式下遮罩仍保持；
- `failed`：启动失败，未进入保护态。

诊断信息不得包含按键内容、密码、窗口文本或截图。

### FR-9 半合盖自动保护

- 功能默认开启，用户在菜单中手动关闭后持久化该选择。
- 支持 `30°`、`45°`、`60°` 三档触发角度，默认 `45°`。
- 角度低于阈值并稳定停留 2 秒才触发，角度仍在变化时重新计时，避免快速或完整合盖误触发。
- 展开判定使用比触发阈值高 `5°` 的迟滞边界。
- 仅由半合盖功能启动的保护可在展开时自动发起认证；手动开启的保护保持原有行为。
- 展开只发起原生 LocalAuthentication，不自动通过认证或直接解除遮罩。
- 完全合盖且检测到外接显示器时抑制本次开合周期，不进入保护，也不在展开时发起认证。
- 合盖导致系统会话锁定时取消当前触发候选，屏幕重新完全展开前不得补触发保护。
- 传感器不存在或读取失败时功能保持不可用，不得使用推测角度触发。
- 读取铰链角度不得要求管理员权限、安装内核扩展或调用外部命令。

## 5. 非功能需求

### NFR-1 性能

- 空闲时 CPU 平均占用目标低于 1%。
- 常驻内存目标低于 50 MB。
- 活动检查不使用忙轮询，最小周期不小于 1 秒。
- Event Tap 回调不得执行阻塞操作。

### NFR-2 隐私

- 默认不联网。
- 默认不采集遥测。
- 日志仅记录状态转换、错误码和时间，不记录输入内容。
- 日志采用轮转和容量上限。

### NFR-3 兼容性

- 仅支持 Apple Silicon 和 Intel 的 macOS。
- MVP 最低版本建议为 macOS 13。
- Touch ID 不可用时必须支持系统密码回退。
- 多显示器、显示器热插拔和全屏 Space 必须纳入验收。

### NFR-4 可维护性

- 主体使用 Go 实现。
- macOS 原生能力通过范围受控的 cgo/Objective-C bridge 提供。
- 原生 bridge 不承载业务状态机。
- 平台专属代码使用 `//go:build darwin`。

## 6. 非目标

- 自动解锁真正的 macOS 锁屏。
- 绕过 FileVault、登录窗口、MDM 或企业安全策略。
- 支持 Windows/Linux。
- 修改目标自动化客户端源码。
- 监听、保存或自动填写用户密码。
- 阻止管理员、root、强制退出或机器重启。
- 保证所有第三方截图方案都看不到保护层。

## 7. MVP 验收标准

1. 已授权的 Mac 上可从菜单栏成功进入保护态。
2. 连续空闲超过系统锁屏阈值后，系统未自动进入锁屏。
3. 保护态下，全部显示器均无底层桌面内容泄露。
4. 物理鼠标和普通按键不会操作底层应用。
5. 自动化客户端的窗口截图、读取 UI 树、点击和输入仍可工作。
6. 物理 Enter 可打开原生认证面板。
7. Touch ID 或系统密码认证成功后完整解除保护。
8. 认证失败或取消后仍保持保护。
9. Event Tap 被系统临时禁用后可恢复；无法恢复时保持遮罩、展示降级状态和故障弹窗，
   用户可从弹窗发起原生身份认证。
10. 检测到明确托管的自动锁屏策略、仅确认设备已纳管或策略检测失败时，开启流程均不展示
    企业策略确认弹窗，Guardian、活动模拟、保护层和输入拦截正常启动。
11. “权限诊断”展示企业策略检测结果，但不要求用户确认。
12. 工具运行期间不修改 `pmset`、屏幕保护程序设置或 Configuration Profile。
13. 应用日志中不存在按键内容、密码、截图和窗口文本。
14. 测试模拟锁屏启用完整遮罩和输入隔离，在全部显示器显示倒计时，并在 15 秒后自动清理；
    正式保护不自动超时。
15. 默认全局快捷键可开启保护，可在菜单切换预设或关闭；保护态下按快捷键不会解除保护。
16. “仅阻止系统锁屏”模式不创建遮罩或 Event Tap，物理输入保持可用，再次点击菜单项可
    直接停止。
17. “仅阻止系统锁屏”运行中仍可通过菜单或全局快捷键开启模拟锁屏；预检失败时保持原
    模式，预检成功后自动切换，且不得同时运行两个 Guardian。
18. 半合盖角度低于所选阈值并稳定时自动进入保护，重新展开后只发起原生认证；手动保护
    不受影响。
19. 完全合盖并连接外接显示器时不触发保护，重新展开时也不出现由本次合盖产生的认证
    面板。

## 8. 风险与待验证项

- 不同自动化客户端及版本可能产生不同的合成事件来源，需要实机验证签名信任规则。
- 全屏保护层是否会进入自动化客户端的全屏截图，需要针对目标客户端验证。
- 合成鼠标移动能否在所有目标 macOS 版本上重置自动锁屏计时，需要实机矩阵验证。
- LocalAuthentication 密码回退的具体 UI 由系统版本和策略决定，应用不能强制其样式。
- Event Tap 无法形成与系统锁屏等价的安全隔离。
- 铰链角度 HID 报告属于机型相关接口，需要针对支持机型和新 macOS 版本持续回归。
